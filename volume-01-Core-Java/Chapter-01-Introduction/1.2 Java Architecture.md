## 1. JDK, JRE and JVM

The three most important components are:

1.  **JDK** --- Java Development Kit
2.  **JRE** --- Java Runtime Environment
3.  **JVM** --- Java Virtual Machine

### JDK --- Java Development Kit

JDK provides the tools required to develop Java applications.

It includes:

-   Java compiler (`javac`)
-   Java launcher (`java`)
-   Debugging tools
-   Other development utilities
-   JVM and runtime components

### JRE --- Java Runtime Environment

JRE provides the environment required to run Java applications.

Traditionally, it includes:

-   JVM
-   Runtime libraries
-   Supporting runtime components

### JVM --- Java Virtual Machine

JVM is responsible for executing Java bytecode.

It handles:

-   Class loading
-   Bytecode verification
-   Memory management
-   Garbage collection
-   Bytecode execution

Think of it this way:

``` text
JDK
 |
 |-- Development Tools
 |
 |-- Runtime Environment
       |
       |-- JVM
       |
       |-- Runtime Libraries
```

*Note: This is the traditional conceptual relationship. Modern Java
distributions don't necessarily package a separate JRE inside the JDK.*

### Important distinctions

Component   Responsibility
  ----------- ---------------------------------------------------
`javac`     Compiles `.java` into `.class`
JVM         Executes bytecode
JRE         Provides the runtime environment
JDK         Provides development tools and runtime components

-   **JVM:** Executes bytecode and handles class loading, verification,
    garbage collection and memory management.
-   **JDK:** Provides development tools, including the compiler, along
    with runtime components.
-   Java applications can be executed without a full JDK if a compatible
    runtime is available. A compiler is not needed once the source code
    has already been compiled.
-   Having a JDK doesn't mean Java automatically compiles your
    application. You still need to invoke the compiler, either manually
    or through a build tool such as Maven.
-   Modern Java distributions don't necessarily provide a separate JRE
    installation. You can create a custom runtime using `jlink`.
-   The JVM manages garbage collection by identifying objects that are
    no longer reachable and reclaiming their memory.

## 2. Java compilation and execution

Consider this command:

``` bash
javac HelloWorld.java
```

It generates:

``` text
HelloWorld.class
```

-   `javac` is the Java compiler. It converts source code into bytecode.
-   The JVM does not need the complete JDK to execute bytecode; it needs
    a compatible runtime environment.
-   A `.class` file can be executed if a compatible Java runtime is
    available, even without a compiler.

When you execute:

``` bash
java HelloWorld
```

the JVM performs a sequence of steps.

### What happens internally?

1.  **Class Loading:** Class Loader loads `HelloWorld.class` into JVM
    memory.
2.  **Bytecode Verification:** Verifier checks whether the bytecode is
    valid and safe to execute.
3.  **Linking:** Includes verification, preparation and resolution.
4.  **Initialization:** Static variables are assigned their explicit
    values and static initialization blocks are executed.
5.  **Execution:** Execution Engine executes the bytecode using
    interpretation and JIT compilation.

Simplified flow:

``` text
       java HelloWorld
              |
              v
        Class Loader
              |
              v
      Bytecode Verifier
              |
              v
           Linking
              |
              v
        Initialization
              |
              v
       Execution Engine
              |
              v
           Output
```

JVM doesn't simply execute bytecode immediately. Class loading,
verification, linking and initialization happen as part of the class
execution lifecycle.

## 3. PATH and CLASSPATH

-   `PATH` → Where Windows finds Java executable commands.
-   `CLASSPATH` → Where Java looks for compiled classes and JAR
    dependencies.

You don't always need to configure the `CLASSPATH` environment variable.
You can specify it directly.

``` bash
java -cp C:\JavaPrograms Test
```

Or use the current directory:

``` bash
java -cp . Test
```

Here, `.` represents the current directory.

### `java Test` vs `java -cp . Test`

`java Test` uses the default classpath. If you haven't explicitly
configured `CLASSPATH`, Java normally uses the current working directory
(`.`) as its default classpath. So, if `Test.class` is in your current
directory, this works:

``` bash
java Test
```

With:

``` bash
java -cp . Test
```

-   `-cp` explicitly sets the classpath.
-   `.` means the current directory.
-   `Test` is the class name.

Both commands can execute `Test.class` when it is in the current
directory.

  -----------------------------------------------------------------------
Command                             Behaviour
  ----------------------------------- -----------------------------------
`java Test`                         Uses the default classpath

`java -cp . Test`                   Explicitly uses the current
directory

`java -cp C:\JavaPrograms Test`     Searches in the specified directory
-----------------------------------------------------------------------

## 4. JAR files

JAR stands for **Java Archive**.

It is a file that packages multiple Java-related resources into a single
file.

A JAR can contain:

-   Compiled `.class` files
-   Images and other resources
-   Configuration files
-   Metadata
-   Manifest file

### Why do we need JAR files?

Imagine your application has 100 Java classes. Instead of distributing
100 individual `.class` files, you can package them into one JAR file.

Example:

``` text
EmployeeApplication/
    Employee.class
    Department.class
    Salary.class
    Main.class
```

These can be packaged into:

``` text
EmployeeApplication.jar
```

### Creating and running a JAR

Suppose you have:

``` java
public class Main {

    public static void main(String[] args) {
        System.out.println("Hello from JAR!");
    }
}
```

Compile:

``` bash
javac Main.java
```

Create a JAR:

``` bash
jar --create --file app.jar Main.class
```

Run a normal JAR by specifying the class:

``` bash
java -cp app.jar Main
```

Output:

``` text
Hello from JAR!
```

### Normal JAR vs Executable JAR

**Normal JAR**

Contains classes and resources, but doesn't necessarily specify an
application entry point.

Run using:

``` bash
java -cp app.jar Main
```

**Executable JAR**

Contains a manifest specifying the main class.

Create one:

``` bash
jar --create --file app.jar --main-class Main Main.class
```

Run it:

``` bash
java -jar app.jar
```

The Java launcher reads the `Main-Class` entry from the manifest.

Example manifest:

``` text
Manifest-Version: 1.0
Main-Class: com.example.Main
```

  -----------------------------------------------------------------------
Normal JAR                          Executable JAR
  ----------------------------------- -----------------------------------
Main class specified in command     Main class specified in manifest

`java -cp app.jar Main`             `java -jar app.jar`

Doesn't require a `Main-Class`      Requires a `Main-Class` manifest
manifest entry                      entry
  -----------------------------------------------------------------------

**Important:** When using `java -jar`, the regular `-cp` setting is
ignored. Dependencies must be made available through the JAR manifest or
another packaging/runtime mechanism.

### External JAR dependencies

Classpath tells Java where to find compiled classes and JAR
dependencies.

Example project:

``` text
JavaProject/
    classes/
        Main.class
        Employee.class

    libraries/
        mysql-connector.jar
```

On Windows:

``` bash
java -cp "classes;libraries/mysql-connector.jar" Main
```

On Linux/macOS:

``` bash
java -cp "classes:libraries/mysql-connector.jar" Main
```

You can also include all JAR files inside a `lib` directory.

Windows:

``` bash
java -cp "classes;lib/*" Main
```

Linux/macOS:

``` bash
java -cp "classes:lib/*" Main
```

Here:

-   `classes` contains application classes.
-   `lib/*` includes JAR files inside the `lib` directory.
-   On Windows, use `;` to separate classpath entries.
-   On Linux and macOS, use `:`.

Example with a packaged application and two dependencies:

``` text
hrms/
├── classes/
│   └── com/asheef/hrms/Main.class
│
└── lib/
    ├── mysql.jar
    └── common.jar
```

Windows command:

``` bash
java -cp "classes;lib/*" com.asheef.hrms.Main
```

### Executable JAR dependencies and Spring Boot

If you execute:

``` bash
java -jar hrms.jar
```

Java reads the `Main-Class` from the manifest, but it doesn't
automatically search the directory for every JAR dependency. If
dependencies aren't packaged or configured, you may get an error such
as:

``` text
NoClassDefFoundError
```

One solution is to specify the application and dependency JARs on the
classpath:

``` bash
java -cp "hrms.jar;mysql-connector.jar;common-utils.jar" com.example.Main
```

This example uses Windows classpath separators.

When we build our Spring Boot application using Maven:

``` bash
mvn clean package
```

Maven compiles the source code, processes resources, runs tests and
packages the application.

Spring Boot's Maven plugin can create an executable JAR containing:

-   Application classes
-   Runtime dependencies
-   Supporting resources
-   Boot launcher and metadata

We can then execute it using:

``` bash
java -jar target/hrms-application.jar
```

This is why we don't normally manually specify every dependency JAR when
running a packaged Spring Boot application.

## 5. Java packages

A **package** is a mechanism for grouping related Java classes and
interfaces.

Packages help:

-   Organize related classes.
-   Avoid naming conflicts.
-   Provide access control.
-   Make large applications maintainable.
-   Improve code organization.

Imagine an HRMS application:

``` text
com.asheef.hrms
    |
    |-- controller
    |      EmployeeController.java
    |
    |-- service
    |      EmployeeService.java
    |
    |-- repository
    |      EmployeeRepository.java
    |
    |-- entity
           Employee.java
```

This is similar to how we organize our actual Spring Boot project.

Example:

``` java
package com.asheef.hrms.entity;

public class Employee {

    public void display() {
        System.out.println("Employee");
    }
}
```

To use this class from another package:

``` java
import com.asheef.hrms.entity.Employee;

public class Main {

    public static void main(String[] args) {
        Employee employee = new Employee();
        employee.display();
    }
}
```

### Compiling classes inside packages

Suppose the project structure is:

``` text
Project/
└── src/
    └── com/
        └── example/
            ├── Main.java
            └── Employee.java
```

Both source files declare:

``` java
package com.example;
```

Compile from the `Project` directory:

``` bash
javac -d classes src/com/example/*.java
```

-   `javac` invokes the compiler.
-   `-d classes` specifies where compiled class files should be placed.
-   `src/com/example/*.java` selects the source files.

The output becomes:

``` text
Project/
├── src/
│   └── com/
│       └── example/
│           ├── Main.java
│           └── Employee.java
│
└── classes/
    └── com/
        └── example/
            ├── Main.class
            └── Employee.class
```

Execute:

``` bash
java -cp classes com.example.Main
```

Output:

``` text
Hello Employee
```

We use the fully qualified class name `com.example.Main`, not `Main`,
because it belongs to the `com.example` package.

### Package vs Classpath vs JAR

-   **Package:** Organizes Java classes logically.
-   **Classpath:** Tells Java where to find classes and libraries.
-   **JAR:** Packages classes and resources into an archive.

These three concepts are related, but they are not the same.

## 6. Java launcher basics

The `java` command is used to launch Java applications.

Command                 Purpose
  ----------------------- ----------------------------------------------
`java Main`             Execute a class
`java -cp . Main`       Execute using current directory as classpath
`java -cp lib/* Main`   Execute using JARs in `lib`
`java -jar app.jar`     Execute an executable JAR
`java -version`         Display runtime version
`java -Xms256m Main`    Set initial heap size
`java -Xmx512m Main`    Set maximum heap size

The `-cp` and `-classpath` options mean exactly the same thing.

``` bash
java -cp app.jar Main
```

``` bash
java -classpath app.jar Main
```

Both specify the classpath.

Other useful JDK tools:

Command     Purpose
  ----------- -------------------------------
`java`      Launches Java applications
`javac`     Compiles Java source code
`javadoc`   Generates documentation
`jdb`       Java debugger
`jar`       Creates and manages JAR files
`jshell`    Interactive Java shell
