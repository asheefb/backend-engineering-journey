

Three most important components:

1. **JDK** — Java Development Kit
2. **JRE** — Java Runtime Environment
3. **JVM** — Java Virtual Machine

### 1. JDK — Java Development Kit

JDK provides the tools required to develop Java applications.

It includes:

* Java compiler (`javac`)
* Java launcher (`java`)
* Debugging tools
* Other development utilities
* JVM and runtime components

### 2. JRE — Java Runtime Environment

JRE provides the environment required to run Java applications.

Traditionally, it includes:

* JVM
* Runtime libraries
* Supporting runtime components

### 3. JVM — Java Virtual Machine

JVM is responsible for executing Java bytecode.

It handles:

* Class loading
* Bytecode verification
* Memory management
* Garbage collection
* Bytecode execution

*Note: This is the traditional conceptual relationship. Modern Java distributions don't necessarily package a separate JRE inside the JDK.*

### Q1. Difference between JDK and JVM

* **JVM:** Executes bytecode, handles class loading, verification, garbage collection and memory management.
* **JDK:** Provides development tools, including the compiler, along with runtime components.

### Q2. Can we execute Java without installing a full JDK?

Yes, we can execute Java applications without a full JDK.

| Component | Responsibility                 |
| --------- | ------------------------------ |
| javac     | Compiles `.java` into `.class` |
| JVM       | Executes bytecode              |
| JRE       | Provides runtime environment   |

**Important:** Having a JDK doesn't mean Java automatically compiles your application. You still need to invoke the compiler, either manually or through a build tool such as Maven.

Also, modern Java distributions don't necessarily provide a separate JRE installation. You can create a custom runtime using `jlink`.

### Q3. Which component handles garbage collection?

The JVM manages garbage collection.

It identifies objects that are no longer reachable and reclaims their memory.

Consider this command:

```bash
javac HelloWorld.java
```

It generates:

```text
HelloWorld.class
```

Now 
1. Does `javac` require JVM to compile the source code? 
   - NO, javac is the Java compiler. It converts source code into bytecode.
2. Does JVM require JDK to execute bytecode? 
   - NO, JVM needs a compatible runtime environment, not the complete development kit.
3. Can we execute a `.class` file if we have a compatible Java runtime but no compiler? 
   - YES becz source code is already compiled

When you execute:

```bash
java HelloWorld
```

The JVM follows a sequence of steps.

### What happens internally?

1. **Class Loading:** Class Loader loads `HelloWorld.class` into JVM memory.
2. **Bytecode Verification:** Verifier checks whether the bytecode is valid and safe to execute.
3. **Preparation and Linking:** JVM prepares class-level structures and resolves symbolic references as needed.
4. **Initialization:** Static variables and static initialization blocks are executed.
5. **Execution:** Execution Engine executes the bytecode using interpretation and JIT compilation.

Simplified architecture:

```text
       java HelloWorld
              |
              v
        Class Loader
              |
              v
      Bytecode Verifier
              |
              v
        Linking
              |
              v
       Initialization
              |
              v
       Execution Engine
              |
              v
          Output
```

JVM doesn't simply execute bytecode immediately. Class loading, verification, linking and initialization happen as part of the class execution lifecycle.

## Path vs CLASSPATH

* `PATH` → Where Windows finds Java executable commands.
* `CLASSPATH` → Where Java looks for compiled classes and JAR dependencies.

You don't always need to configure the `CLASSPATH` environment variable.

You can specify it directly:

```bash
java -cp C:\JavaPrograms Test
```

Or use the current directory:

```bash
java -cp . Test
```

Here, `.` represents the current directory.


### 1. `java Test`

This command uses the default classpath.

If you haven't explicitly configured `CLASSPATH`, Java normally uses the current working directory (`.`) as its default classpath.

So, if `Test.class` is in your current directory, this works:

```bash
java Test
```

### 2. `java -cp . Test`

Here:

* `-cp` explicitly sets the classpath.
* `.` means the current directory.
* `Test` is the class name.

This also executes `Test.class`.

### 3. Compare them

| Command                         | Behaviour                             |
| ------------------------------- | ------------------------------------- |
| `java Test`                     | Uses the default classpath            |
| `java -cp . Test`               | Explicitly uses the current directory |
| `java -cp C:\JavaPrograms Test` | Searches in the specified directory   |
