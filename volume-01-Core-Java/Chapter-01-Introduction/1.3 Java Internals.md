# JVM Introduction

### 1. What exactly is JVM?

JVM stands for **Java Virtual Machine**.

It is an abstract computing machine that provides the runtime environment for executing Java bytecode.

### 2. Why do we need JVM?

Imagine Java didn't have JVM.

Every operating system would need a separate compiler that converts Java source code into its own native machine instructions.

That would make portability difficult.

JVM solves this by providing a common execution environment for Java bytecode.

```text
             Java Source
                  |
                  v
             Java Compiler
                  |
                  v
              Bytecode
                  |
          +-------+-------+
          |       |       |
          v       v       v
       Windows  Linux   macOS
         JVM     JVM     JVM
          |       |       |
          v       v       v
       Execute  Execute Execute
```

Each operating system has a compatible JVM implementation.

The same compatible bytecode can therefore run across different platforms.

### 3. Is JVM hardware or software?

JVM is software.

It acts as a virtual machine by providing an execution environment that abstracts away many operating-system and hardware differences.

### 4. JVM responsibilities

| Responsibility        | Explanation                                     |
| --------------------- | ----------------------------------------------- |
| Class Loading         | Loads compiled classes into memory              |
| Bytecode Verification | Checks bytecode validity                        |
| Memory Management     | Manages runtime memory                          |
| Garbage Collection    | Reclaims memory occupied by unreachable objects |
| Execution             | Executes bytecode                               |
| JIT Compilation       | Optimizes frequently executed code              |

## Interview Questions

**1. What exactly is JVM and why do we need it?**

> JVM stands for Java Virtual Machine. It is a software-based runtime environment that executes Java bytecode. It provides platform independence by allowing the same bytecode to run on different operating systems through compatible JVM implementations. It also manages memory, loads and verifies classes, and performs garbage collection.

**2. Does JVM execute `.java` or `.class` files?**

* `.java` — Java source code.
* `.class` — compiled Java bytecode.
* JVM executes the bytecode contained in `.class` files.

**3. If Java is platform-independent, does that mean JVM is also platform-independent?**

More precisely, JVM implementations are platform-specific, but they follow the JVM specification.

For example:

* Windows → Windows-compatible JVM.
* Linux → Linux-compatible JVM.
* macOS → macOS-compatible JVM.

The same compatible Java bytecode can run on all of them.

### What actually happens?

When you execute:

```bash
java HelloWorld
```

The JVM follows this simplified sequence:

**Step 1: Class Loading**

* Class Loader loads the required `.class` file.
* The class is brought into the JVM.

**Step 2: Linking**

Linking has three stages:

* Verification: Checks whether bytecode is valid and safe.
* Preparation: Allocates memory for static fields and assigns default values.
* Resolution: Resolves symbolic references into direct references.

**Step 3: Initialization**

* Static variables receive their explicitly assigned values.
* Static initialization blocks execute.
* These execute in textual order within the class.

**Step 4: Main Method Execution**

* JVM invokes the `main()` method.

### Example

```java
public class Test {

    static int a = 10;

    static {
        a = 20;
        System.out.println(a);
    }

    public static void main(String[] args) {
        System.out.println(a);
    }
}
```

Expected output:

```text
20
20
```

### Actual execution sequence

**1. Loading**

* Class Loader loads `Test.class`.

**2. Linking**

* Verification: Checks whether the bytecode is valid.
* Preparation: Allocates memory for static variables and assigns default values.

At this point:

```java
static int a = 0;
```

**Important:** During preparation, `a` gets `0`, not `10`.

**3. Initialization**

Now the JVM executes static initializers in textual order.

First:

```java
static int a = 10;
```

So `a = 10`.

Then:

```java
static {
    a = 20;
    System.out.println(a);
}
```

So `a = 20`, and the first output is `20`.

**4. Main method**

JVM invokes `main()`.

```java
System.out.println(a);
```

The current value is still `20`.

Therefore, the second output is `20`.

### Important concept to remember

| Phase                             | Value of `a` |
| --------------------------------- | -----------: |
| Preparation                       |            0 |
| Initialization: static assignment |           10 |
| Initialization: static block      |           20 |
| Main execution                    |           20 |

You correctly identified the sequence. Just remember that **static variables receive default values during preparation, not their explicitly assigned values.**

## 1. JVM Architecture — Overview

The JVM consists of four major components:

1. **Class Loader Subsystem**
2. **Runtime Data Areas (Memory Areas)**
3. **Execution Engine**
4. **JNI (Java Native Interface) and Native Method Libraries**

### 1. Class Loader Subsystem

Its responsibility is to load `.class` files into JVM memory.

For example:

```java
public class Employee {
    public static void main(String[] args) {
        System.out.println("Hello Employee");
    }
}
```

When you execute:

```bash
java Employee
```

The Class Loader Subsystem loads the required classes into the JVM.

It also participates in the linking and initialization process.

We'll explore:

* Bootstrap ClassLoader
* Platform ClassLoader
* Application ClassLoader
* Parent Delegation Model
* Loading, Linking and Initialization

### 2. Runtime Data Areas

This is where JVM manages memory during program execution.

It includes:

| Memory Area         | Purpose                                             |
| ------------------- | --------------------------------------------------- |
| Heap                | Stores objects and arrays                           |
| Java Stack          | Stores method frames and local variables            |
| Method Area         | Stores class-level structures and runtime constants |
| PC Register         | Tracks the current JVM instruction for each thread  |
| Native Method Stack | Supports execution of native methods                |

### 3. Execution Engine

Once classes are loaded and the necessary memory is allocated, the Execution Engine executes the bytecode.

Its important components include:

* Interpreter
* JIT Compiler
* Garbage Collector

**Interpreter:** Executes bytecode instructions.

**JIT Compiler:** Compiles frequently executed bytecode into native machine code to improve performance.

**Garbage Collector:** Reclaims memory occupied by objects that are no longer reachable.

### 4. JNI and Native Method Libraries

Sometimes Java applications need functionality implemented in other programming languages, such as C or C++.

JNI allows Java code to interact with native code.

For example, a Java application might use a native library to access operating-system functionality.

## 1. Heap Memory

Heap is the runtime memory area where Java objects and arrays are allocated.

Example:

```java
public class Employee {

    int salary = 30000;

    public static void main(String[] args) {
        Employee emp = new Employee();
    }
}
```

Conceptually, memory looks like this:

```text
          STACK                  HEAP
      ┌────────────┐       ┌────────────────┐
      │            │       │                │
      │ emp ─────────────────► Employee     │
      │            │       │ salary = 30000 │
      └────────────┘       └────────────────┘
```

Important characteristics:

* Objects and arrays are allocated in Heap.
* Heap is shared among threads.
* Garbage Collector manages object memory.
* Objects remain allocated while memory is needed and they remain reachable.

## 2. Java Stack Memory

Every thread has its own Java Stack.

Whenever a method is called, JVM creates a **Stack Frame** for that method.

A stack frame contains:

* Local variables.
* Operand stack.
* Runtime constant pool reference.
* Method execution information.

Example:

```java
public class Demo {

    public static void main(String[] args) {
        int a = 10;
        int b = 20;

        calculate();
    }

    static void calculate() {
        int x = 100;
        int y = 200;
    }
}
```

Conceptually:

```text
        JAVA STACK

    ┌──────────────────┐
    │ calculate()      │
    │ x = 100          │
    │ y = 200          │
    ├──────────────────┤
    │ main()           │
    │ a = 10           │
    │ b = 20           │
    └──────────────────┘
```

When `calculate()` finishes, its stack frame is removed.

When `main()` finishes, its stack frame is removed.

**Important:** Each thread has its own stack, so one thread's local variables are not directly shared with another thread.

## 3. Heap vs Stack

| Feature           | Heap                                         | Stack                                      |
| ----------------- | -------------------------------------------- | ------------------------------------------ |
| Stores            | Objects and arrays                           | Stack frames and local variables           |
| Sharing           | Shared across threads                        | Each thread has its own                    |
| Memory management | Garbage Collector manages object reclamation | Frames are pushed and popped automatically |
| Lifetime          | Depends on object reachability and GC        | Associated with method execution           |
| Typical error     | OutOfMemoryError                             | StackOverflowError                         |
