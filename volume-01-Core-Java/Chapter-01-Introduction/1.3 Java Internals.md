# JVM Introduction

### 1. What exactly is JVM?

JVM stands for **Java Virtual Machine**.

It is an abstract computing machine that provides the runtime environment for executing Java bytecode.

### 2. Why do we need JVM?

Imagine Java didn't have JVM.

Every operating system would need a separate compiler that converts Java source code into its own native machine instructions.

That would make portability difficult.

JVM solves this by providing a common execution environment for Java bytecode.

```text
             Java Source
                  |
                  v
             Java Compiler
                  |
                  v
              Bytecode
                  |
          +-------+-------+
          |       |       |
          v       v       v
       Windows  Linux   macOS
         JVM     JVM     JVM
          |       |       |
          v       v       v
       Execute  Execute Execute
```

Each operating system has a compatible JVM implementation.

The same compatible bytecode can therefore run across different platforms.

### 3. Is JVM hardware or software?

JVM is software.

It acts as a virtual machine by providing an execution environment that abstracts away many operating-system and hardware differences.

### 4. JVM responsibilities

| Responsibility        | Explanation                                     |
| --------------------- | ----------------------------------------------- |
| Class Loading         | Loads compiled classes into memory              |
| Bytecode Verification | Checks bytecode validity                        |
| Memory Management     | Manages runtime memory                          |
| Garbage Collection    | Reclaims memory occupied by unreachable objects |
| Execution             | Executes bytecode                               |
| JIT Compilation       | Optimizes frequently executed code              |

## Interview Assessment Questions

**1. What exactly is JVM and why do we need it?**

> JVM stands for Java Virtual Machine. It is a software-based runtime environment that executes Java bytecode. It provides platform independence by allowing the same bytecode to run on different operating systems through compatible JVM implementations. It also manages memory, loads and verifies classes, and performs garbage collection.

**2. Does JVM execute `.java` or `.class` files?**

* `.java` — Java source code.
* `.class` — compiled Java bytecode.
* JVM executes the bytecode contained in `.class` files.

**3. If Java is platform-independent, does that mean JVM is also platform-independent?**

More precisely, JVM implementations are platform-specific, but they follow the JVM specification.

For example:

* Windows → Windows-compatible JVM.
* Linux → Linux-compatible JVM.
* macOS → macOS-compatible JVM.

The same compatible Java bytecode can run on all of them.
