## 1. What exactly is JVM?

JVM stands for Java Virtual Machine.

It is an abstract computing machine that provides the runtime environment for executing Java bytecode.

### Why do we need JVM?

Without JVM, every operating syst`em would need a separate compiler to convert Java source code into its native machine instructions.

JVM solves this problem by providing a common execution environment for Java bytecode.

```text
             Java Source
                  |
                  v
             Java Compiler
                  |
                  v
              Bytecode
                  |
          +-------+-------+
          |       |       |
          v       v       v
       Windows  Linux   macOS
         JVM     JVM     JVM
          |       |       |
          v       v       v
       Execute  Execute Execute
```

The same compatible bytecode can run on different operating systems through their respective JVM implementations.

### Is JVM hardware or software?

JVM is software. It acts as a virtual machine by providing an execution environment that abstracts operating-system and hardware differences.

### JVM Responsibilities

| Responsibility | Explanation |
| --- | --- |
| Class Loading | Loads compiled classes into memory |
| Bytecode Verification | Checks bytecode validity |
| Memory Management | Manages runtime memory |
| Garbage Collection | Reclaims memory occupied by unreachable objects |
| Execution | Executes bytecode |
| JIT Compilation | Optimizes frequently executed code |

## 2. How JVM Executes a Java Program

When you execute:

```bash
java HelloWorld
```

The JVM follows these steps:

1. Class Loading
   Class Loader loads the required `.class` files into JVM memory.
2. Linking
   Linking consists of three stages:
    - Verification: Checks bytecode validity.
    - Preparation: Allocates memory for static fields and assigns default values.
    - Resolution: Resolves symbolic references into direct references.
3. Initialization
    - Static variables receive their explicitly assigned values.
    - Static initialization blocks execute.
    - Both execute in textual order within the class.
4. Main Method Execution
   JVM invokes the `main()` method.

### Example: Static Variable Initialization


```java
public class Test {

    static int a = 10;

    static {
        a = 20;
        System.out.println(a);
    }

    public static void main(String[] args) {
        System.out.println(a);
    }
}
```

Output:

```text
20
20
```

### Actual execution sequence

1. Loading

Class Loader loads `Test.class`.

2. Preparation

Memory is allocated for the static variable, and it receives its default value.

```java
static int a = 0;
```

3. Initialization

First, the explicit static assignment executes:

```java
static int a = 10;
```

Now `a = 10`.

Next, the static block executes:

```java
static {
    a = 20;
    System.out.println(a);
}
```

Now `a = 20`, and the first output is `20`.

4. Main Method

```java
System.out.println(a);
```

The current value is still `20`.

Therefore, the second output is also `20`.

| Phase | Value of `a` |
| --- | --- |
| Preparation | 0 |
| Static assignment | 10 |
| Static block | 20 |
| Main execution | 20 |

Important: Static variables receive default values during preparation, not their explicitly assigned values.

# 3. JVM Architecture

The JVM consists of four major components:

1. Class Loader Subsystem
2. Runtime Data Areas
3. Execution Engine
4. JNI and Native Method Libraries

### 1. Class Loader Subsystem

Its responsibility is to load `.class` files into JVM memory.

For example:

```java
public class Employee {

    public static void main(String[] args) {
        System.out.println("Hello Employee");
    }
}
```

When you execute:

bash

```bash
java Employee
```

The Class Loader Subsystem loads the required classes.

It also participates in linking and initialization.

Important concepts:

- Bootstrap ClassLoader
- Platform ClassLoader
- Application ClassLoader
- Parent Delegation Model
- Loading, Linking and Initialization

### 2. Runtime Data Areas

Runtime Data Areas are the memory areas used by JVM during program execution.

They consist of five major areas:

| Memory Area | Purpose |
| --- | --- |
| Heap | Stores objects and arrays |
| Java Stack | Stores method frames and local variables |
| Method Area | Stores class-level structures and runtime constant pools |
| PC Register | Tracks the current JVM instruction for each thread |
| Native Method Stack | Supports native method execution |

### 3. Execution Engine

The Execution Engine executes the loaded bytecode.

Its important components are:

- Interpreter: Executes bytecode instructions.
- JIT Compiler: Compiles frequently executed bytecode into native machine code to improve performance.
- Garbage Collector: Reclaims memory occupied by unreachable objects.

### 4. JNI and Native Method Libraries

JNI stands for Java Native Interface.

It allows Java applications to interact with native code written in languages such as C and C++.

For example, Java applications can use native libraries to access operating-system functionality.

# 4. JVM Runtime Data Areas – Memory Management

Runtime Data Areas are divided into different memory regions.

Let's understand each one.

## 4.1 Heap Memory

Heap is the runtime memory area where Java objects and arrays are allocated.

### Example

```java
public class Employee {

    int salary = 30000;

    public static void main(String[] args) {
        Employee emp = new Employee();
    }
}
```

### Important Characteristics

- Objects and arrays are allocated in Heap.
- Heap is shared among threads.
- Garbage Collector manages object memory.
- Objects can be reclaimed when they are no longer reachable and eligible for garbage collection.

## 4.2 Java Stack Memory

Every JVM thread has its own Java Stack.

Whenever a method is called, JVM creates a Stack Frame for that method.

Each stack frame contains:

- Local variables.
- Operand stack.
- Reference to the runtime constant pool.
- Method execution information.

### Example

```java
public class Demo {

    public static void main(String[] args) {

        int a = 10;
        int b = 20;

        calculate();
    }

    static void calculate() {

        int x = 100;
        int y = 200;
    }
}
```

### What happens internally?

1. JVM creates a stack frame when `main()` is called.
2. When `calculate()` is called, another frame is pushed onto the stack.
3. When `calculate()` finishes, its frame is removed.
4. When `main()` finishes, its frame is removed.

### Important Characteristics

- Each thread has its own Java Stack.
- Stack frames are created and removed automatically.
- Local primitive variables and local references are stored in stack frames.
- Objects referenced by local variables are generally allocated in Heap.
- Each method execution has its own stack frame.

## 4.3 Heap vs Stack

| Feature | Heap | Stack |
| --- | --- | --- |
| Stores | Objects and arrays | Stack frames and local variables |
| Sharing | Shared among threads | Each thread has its own |
| Memory management | Garbage Collector | Frames pushed and popped |
| Lifetime | Depends on object reachability and GC | Associated with method execution |
| Typical error | OutOfMemoryError | StackOverflowError |

## 4.4 Method Area

Method Area is a logical runtime memory area that stores class-level structures.

It includes:

- Class metadata.
- Runtime constant pool.
- Method information and bytecode.
- Field information.

Important: In HotSpot JVM, class metadata is generally stored in Metaspace, which is allocated in native memory.

## 4.5 PC Register (Program Counter Register)

PC stands for Program Counter.

It is a small memory area associated with each JVM thread.

Its responsibility is to track the current JVM instruction being executed by that thread.

Think of it like a bookmark in a book. It remembers your current reading position so you can continue from there.

### Why does every thread need its own PC Register?

Consider this example:

```java
public class Test {

    public static void main(String[] args) {

        Thread t1 = new Thread(() -> {
            for (int i = 0; i < 5; i++) {
                System.out.println("Thread 1: " + i);
            }
        });

        Thread t2 = new Thread(() -> {
            for (int i = 0; i < 5; i++) {
                System.out.println("Thread 2: " + i);
            }
        });

        t1.start();
        t2.start();
    }
}
```

Both threads execute instructions independently.

For example:

- Thread 1 might currently be executing `i++`.
- Thread 2 might currently be executing `System.out.println()`.

Each thread needs its own PC Register to independently track its execution position.

### What happens during thread switching?

1. Thread 1 executes an instruction.
2. Operating system scheduler switches execution to Thread 2.
3. Thread 2 continues its execution.
4. Later, Thread 1 gets CPU time again and resumes its execution.

Important: The PC Register tracks the current JVM instruction. Actual thread scheduling and context switching are handled by the underlying execution environment and operating system.

### Interview Points

| Feature | PC Register |
| --- | --- |
| Full form | Program Counter Register |
| Associated with | Each JVM thread |
| Purpose | Tracks current JVM instruction |
| Sharing | Thread-private |
| Error | No specific PC-register error |

Special point: When a thread executes a Java method, its PC Register identifies the current JVM bytecode instruction. When it executes a native method, its PC Register value is undefined.

## 4.6 Native Method Stack

Java applications sometimes need to execute code written in languages other than Java, particularly C and C++.

### Example

```java
public class Test {

    public native void calculate();

    public static void main(String[] args) {

        Test obj = new Test();
        obj.calculate();
    }
}
```

Here:

```java
public native void calculate();
```

The `native` keyword indicates that the method implementation is provided by native code rather than Java bytecode.

### What happens internally?

1. Java calls the native method.
2. JVM uses JNI to interact with native code.
3. Native code executes using the underlying native execution environment.
4. The result can be returned to Java.

The Native Method Stack supports native method execution.

### Java Stack vs Native Method Stack

| Java Stack | Native Method Stack |
| --- | --- |
| Supports Java method execution | Supports native method execution |
| Uses JVM stack frames | Supports native execution state |
| Associated with each thread | Supports native execution by threads |

Note: JVM implementations may combine these stacks or implement native execution differently.
